Fix a server error when a nested array has the same name as its parent array and the parent's items contain an area. Nested objects that share a name with their parent object are fixed as well. When docs are loaded or saved, array items and objects are now annotated with the `_id` of their own field as `_arrayFieldId` or `_objectFieldId`, so each is matched to its own schema. Like other properties beginning with `_`, these are not stored. `scopedArrayName` and `scopedObjectName` are no longer written or read, so the `arrayName` and `objectName` field options no longer have any effect, `apos.schema.getArrayManager` and `getObjectManager` now take a field `_id` and return the field itself, and the `apos.schema.arrayManagers` and `objectManagers` properties have been removed. `apos.util.getManagerOf` throws an error for an array item or object that was not annotated, such as content read directly from the database; call `apos.schema.annotateFieldIds(doc)` on such content first. Thanks to [Michael Lip](https://github.com/theluckystrike) for bringing this issue to our attention.
