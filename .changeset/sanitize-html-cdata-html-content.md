Security: outside SVG and MathML, browsers parse `<![CDATA[` as a bogus comment that ends at the first `>`, but the underlying parser read it all the way to `]]>`. Markup between those two points was hidden from sanitize-html, so a start tag for one of the `nonTextTags` (such as `noscript`, `style`, `script`, `textarea` or `xmp`) placed there was not seen, and content the browser would keep inert inside that element was emitted as live markup. The parser also did not recognize where browsers leave SVG or MathML content (for example at a `<p>` or `<div>` start tag inside `<svg>`), so after that point it could read a CDATA section, or the content of an element such as `<style>`, as markup where browsers read it as text. Only tags, attributes and URL schemes permitted by the allowlist could be emitted this way. sanitize-html now follows where browsers' SVG and MathML content begins and ends, reads CDATA sections and raw text elements as browsers do, and keeps discarding a `<noscript>` (when it is one of the `nonTextTags`) up to its end tag even when it starts inside other discarded content. Real CDATA sections in SVG and MathML are still kept as text. Where browsers themselves build different trees, the rest of the input is discarded (CWE-79, CWE-436, GHSA-2rjc-9xvg-45j7).

Thanks to [Oscar Rodríguez](https://github.com/Ramiin) for reporting the vulnerability.
