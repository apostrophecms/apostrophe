"@apostrophecms/import-export": patch
"apostrophe": patch

Security: export downloads are published under the public `/uploads/exports/` URL until they expire, and their file names were built only from the site's short name, the exported type and a timestamp to the second, so anyone could guess the URL of a fresh export and download it without logging in. Export file names now include a random 128-bit component, and the type in the name is reduced to a slug so it can no longer place the file outside the exports folder. Likewise, while an import is pending (for instance waiting for the user to decide about duplicates or a different locale), the uploaded archive, which can be a whole site export, is kept under the public `/uploads/import-export/` URL so that any server can resume the import, and its name started with an id that was not generated from a secure random source. That name is now a random 128-bit value plus the file extension, and no longer includes any part of the uploaded file's name. In core, the chunks of a big upload (used by import and other large uploads) are likewise kept under the public `/uploads/big-uploads/` URL while the upload is in progress, named after an upload id that was not generated from a secure random source; that id is now a random 128-bit value too. Exposure was limited: a privileged user had to have just run an export, the download is removed after 10 minutes by default, a pending import archive's URL contained a random id known only to the uploader and only existed until the import ended, big-upload chunks only existed while an upload was in progress and their id was only known to the uploader, and sites serving uploads from private storage were not affected (CWE-200, CWE-330, GHSA-5gc8-frw3-3vqm).

Thanks to [tikisan_](https://github.com/tikipiya) for reporting the vulnerability.
