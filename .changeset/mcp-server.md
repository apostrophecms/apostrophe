Adds `@apostrophecms/mcp`, an MCP server that lets an outside AI tool, such as Claude, ChatGPT or an IDE, work on the site's content as a connected user. It is off unless `enabled: true` is set. The outside tool brings its own model, so this module never calls Apostrophe's AI. It serves one route, `/api/v1/@apostrophecms/mcp`, for both current (2026-07-28) and 2025-era MCP clients. Its tools are the content tools the assistant uses, limited to what the connected user may read and change. Every change is saved as a draft, marked as made by AI, and recorded in the change log. The result of each change carries a request id, and the `get_changes` tool takes that id to report what changed. The connected user comes only from a bearer token in the `Authorization` header: an access token from `@apostrophecms/oauth`, which the MCP server turns on (so enabling MCP now requires the site's `baseUrl`), so the user approves each tool once on the site's approval page and can disconnect it under "Connected tools". A session cookie, an API key, or a token sent in the query string, the body or a cookie is ignored. A request without a valid token gets a 401 response that points the tool at the server's OAuth metadata, which is how MCP clients find where to ask for approval. For development only, `APOS_MCP_DEV_TOKEN=<token>:<username>` connects as that user, and keeps working when the OAuth server is turned off with `enabled: false`. It is ignored in production. The harness refuses an AI write to a document that was saved after the AI read it. Over MCP, each connection remembers what it read across tool calls, so an outside tool can't overwrite edits made after it read a document. A refused write tells the AI who saved the document: when it was another user, the AI is told to say what they changed and to write only if the user asks; when it was the same user, in the admin UI or another of their chats or tools, it reads the document again and builds on that save. This applies to the assistant too. Each connection remembers its 100 most recently read or written documents; the `seenLimit` option changes that. A browser request whose `Origin` names another host is refused. The `allowedOrigins` option lists the hostnames allowed, and by default it is `baseUrl`'s hostname, or localhost when `baseUrl` is not set.
