Security: for anonymous REST API requests restricted by `publicApiProjection`, the `sort` query parameter and the per-field filter query parameters could operate on fields excluded by the projection, revealing the relative order of hidden values or which documents had a given hidden value. Sort keys and field filters not permitted by the projection are now ignored for these requests. In addition, the related pages embedded in anonymous page REST API responses (`_ancestors` and `_children`) were not limited to `publicApiProjection` when the projection included `path`; they now are. Documents loaded through relationships were also returned with every field, whatever the `publicApiProjection` of their own type, even if their type had no public REST API at all. For these requests, each related document, at any depth (including reverse relationships, nested relationships and relationships in widgets, array and object fields), is now limited to the `publicApiProjection` of its own type, or left out if its type has no `publicApiProjection`. Images and files reached this way (for instance in image and file widgets) are still included when their type has no `publicApiProjection`, limited to their title, alt text or description, credit and attachment. **This may change what your public REST API returns** for other related documents. Areas rendered with `render-areas` and server-side page rendering are unchanged. Authenticated requests and API key requests are not affected. Only sites that set `publicApiProjection` were affected. Full text search (`search`, `autocomplete`) is unchanged: it covers every field not marked `searchable: false`, exactly as the public site search does, so sensitive text fields should be marked `searchable: false` (CWE-200, CWE-639, GHSA-rqgm-cfrp-4hx8).
